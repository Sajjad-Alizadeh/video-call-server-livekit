# LiveKit backend implementation plan

**Goal:** Connect this Node.js backend to a separately self-hosted LiveKit server.

**Architecture:** Use the official JavaScript server SDK for scoped join tokens and room APIs. Keep the existing built-in HTTP server, protect privileged routes with a backend-only bearer key, and configure server credentials through environment variables.

**Tech stack:** Node.js 24, livekit-server-sdk 2.19.1, node:http, node:test.

**Constraints:** Keep it simple. User will Dockerize and deploy to Ubuntu later. Do not add deployment infrastructure or client UI.

- [x] Add config validation in `src/config.js` and SDK integration in `src/livekit.js`. Use separate internal HTTP and client WebSocket URLs; tokens expire after ten minutes and grant access to one room only.
- [x] Add `src/app.js` with authenticated token, room list/create, and readiness endpoints. Validate JSON bodies, cap request size, return generic upstream errors, and keep liveness independent of LiveKit.
- [x] Update `src/server.js` for configuration and graceful shutdown; add `test/*.test.js` to verify configuration, signed grants, authentication, validation, and upstream failure behavior.
- [x] Document local `livekit-server --dev`, environment setup, curl usage, trusted backend authentication boundary, and future Ubuntu deployment requirements in `README.md` and `.env.example`.
- [x] Run syntax checks and tests, then verify SDK room operations against a temporary real LiveKit server when available. Report media connectivity separately from API verification.
